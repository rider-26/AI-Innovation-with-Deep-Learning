04 · Wide-and-deep model (Jadon)¶

Question this model answers: does adding memorised rules help the neural network?

Wide-and-deep has two parts, trained together with one loss:

Part What it is Input What it is good at
Wide A linear layer: one weight per rule, like logistic regression 0/1 flags + crossed features chosen in wide_deepEDA.ipynb (e.g. tier x recency bucket) Memorising simple rules such as "Gold and ordered in the last 30 days → likely to buy"
Deep An MLP The same inputs as the plain MLP: all 69 features, scaled numbers + one-hot text Generalising: smooth, complex patterns

probability = sigmoid( wide(rules) + deep(features) )

How the question is answered: an ablation. Same split, same seed, same training code, with one part switched off at a time:

Model Wide Deep Equivalent to
Deep only off on a plain MLP
Wide only on off logistic regression on the rules
Wide + deep on on my model

If wide + deep beats deep only by more than the seed-to-seed noise, the memorised rules help.

Section What it does
0 Setup, data, shared split
1 Build the two inputs (fitted on train only)
2 First run of the three ablation models
3 Tuning: crosses, deep-part size, learning rate (every run logged)
4 Stability: the ablation repeated over 3 seeds
5 Calibration: make 0.7 mean "about 70% buy"
6 Final evaluation on test (used once), against the shared baselines
7 What the wide part memorised
8 Save, and findings

1. The two inputs¶

  • Deep input: build_preprocessor() from src/data_prep.py, the same one the baselines and the plain MLP use (median imputation, scaling, one-hot). Fitted on train only.
  • Wide input: WideFeatures from src/wide_deep.py, built from the crosses the EDA kept. Bucket edges and the list of combinations are learned on train only. A combination with fewer than 30 train customers is merged into "infrequent", so no rule is learned from a handful of people.

2. First run of the three ablation models¶

Starting settings (not tuned yet): deep part 64 → 32, dropout 0.2, Adam learning rate 1e-3, batch 512, early stopping on validation PR-AUC with patience 8. Every run, here and in Section 3, is added to the tuning log.

In [4]:
tuning_log = []          # one row per training run: the evidence of optimisation

def run(name, crosses, config, wide=None, seed=SEED, log=True):
    # Train one model and record its settings and validation PR-AUC.
    wf, W_tr, W_va, W_te = wide if wide is not None else wide_inputs(crosses)
    start = time.perf_counter()
    model, history = train_model((W_tr, D_train), y_train, (W_va, D_val), y_val, config, seed=seed)
    row = {"run": len(tuning_log) + 1, "model": name, "seed": seed,
           "crosses": len(crosses) if config.use_wide else 0,
           "wide_rules": W_tr.shape[1] if config.use_wide else 0,
           **config.as_dict(), "best_epoch": model.best_epoch, "epochs_run": len(history),
           "val_pr_auc": history["val_pr_auc"].max(), "seconds": round(time.perf_counter() - start, 1)}
    if log:
        tuning_log.append(row)
    print(f"{name:<40} val PR-AUC {row['val_pr_auc']:.4f}  (best epoch {model.best_epoch}, {row['seconds']}s)")
    return {"model": model, "history": history, "wide": (wf, W_tr, W_va, W_te), "row": row}

3. Tuning¶

Three things are tuned, one at a time, each step keeping the best setting from the step before (a greedy search: 11 runs instead of the hundreds a full grid would need, and each step is easy to explain). Every choice is made on validation PR-AUC; the test split is not touched.

  1. Which crosses go in the wide part: none (flags only), the top 1, top 3, or all the EDA kept.
  2. Deep-part size: 32, 64 → 32, 128 → 64.
  3. Learning rate: 3e-4, 1e-3, 3e-3.
  4. Weight decay on the wide part: how hard rules backed by little data are shrunk to zero.

4. Stability: the ablation over 3 seeds¶

One run per model can be lucky. Each of the three ablation models is trained with the chosen settings and 3 different seeds. The answer to the question is the mean difference between wide + deep and deep only, compared with the standard deviation across seeds.

5. Calibration¶

The agent reads the probability directly ("0.7 means about 70% buy"), so it must be calibrated. Platt scaling fits a one-input logistic regression from the model's raw score to the outcome, on the validation split. It only rescales the scores, so the ranking (and PR-AUC, ROC-AUC) does not change. The final model is the seed-42 wide + deep run with the chosen settings.

6. Final evaluation on the test split (used once)¶

Everything above is frozen. The test split is scored once, with the threshold from validation, by the same evaluate() every member uses. The baselines come from results/baseline_results.csv (made by 01_baselines.ipynb), so all models are on identical rows.

test_scores = {}
my_rows = []
for name, runs in seed_runs.items():
    r = runs[0]                                           # seed 42 of each ablation model
    _, _, Wv, Wt = r["wide"]
    if name == "Wide + deep":
        t_score = calibrator.predict_proba(predict_logit(r["model"], Wt, D_test))
        v_score, thr = val_prob, threshold
    else:
        v_score = predict_logit(r["model"], Wv, D_val)
        t_score = predict_logit(r["model"], Wt, D_test)
        thr = best_f1_threshold(y_val, v_score)

    my_rows.append({"model": label, "split": "test", **evaluate(y_test, t_score, thr)})

7. What the wide part memorised¶

Each wide input has one weight. A positive weight pushes the customer towards buying, on top of what the deep part says. These are the rules the model memorised, and they are the part of the model a CRM executive can read.

Findings¶

  1. Does adding memorised rules help? No, not measurably. Over 3 seeds, wide + deep averages validation PR-AUC 0.5650 against 0.5641 for deep only: a gain of +0.001 (per seed +0.004, -0.001, -0.000). The seed-to-seed noise is 0.0012, so the gain is within the noise. On test, deep only is slightly ahead (0.585 against 0.581). The deep part already learns the interactions the EDA found, which matches the EDA's warning that they are small. Wide only (0.487) is far behind: the rules alone are not enough.

  2. Against the baselines (test split).

    | Model | PR-AUC | Precision in top 10% | F1 | |---|---|---|---| | Recency rule (what CRM does today) | 0.366 | 0.437 | 0.457 | | Logistic regression | 0.577 | 0.626 | 0.543 | | LightGBM | 0.576 | 0.605 | 0.543 | | Deep only | 0.585 | 0.631 | 0.544 | | Wide + deep | 0.581 | 0.619 | 0.550 |

    Both neural models beat the recency rule by a wide margin (PR-AUC +0.21; 616-626 buyers in the top 1,000 against about 146 at random). Against logistic regression and LightGBM the gain is small (+0.004 to +0.009 PR-AUC), about the size of the seed noise, so I call them level. As the baseline notebook found, the signal is mostly simple and additive, which a linear model already captures.

  3. What tuning changed. All 10 wide + deep runs fall between 0.560 and 0.567 validation PR-AUC, so tuning moved the score very little. The learning rate gave the biggest single step (3e-3 gave +0.002 over 1e-3 and reached its best epoch at 8 instead of 19). Using all 8 crosses was best, but flags only, top 1 and top 3 were within 0.004, about the size of the per-seed differences in Section 4. A smaller deep part (one layer of 32) was as good as 64 -> 32 and better than 128 -> 64. The wide-part weight decay made no difference (0.5670 against 0.5668).

  4. The memorised rules match the EDA:

    • Lapsed customers (181 days or more) who still visited 5+ times in 90 days get the largest push towards buying (+0.24): the "still browsing" group from the EDA heatmap.
    • Platinum customers with 0-1 visits in 90 days (-0.37) or none in 30 days (-0.34) get the largest push away: the tier alone overstates them once they stop visiting.
    • Platinum customers last seen 31-60 days ago get a push up (+0.15): recency matters most for the top tier, as in Section 1 of the EDA.

    The wide part's contribution varies far less than the deep part's (std 0.37 against 2.27), so the deep part makes most of the decision.

  5. Calibration. The raw model was already close to calibrated (pos_weight = 1). Platt scaling improved the Brier score only slightly (0.0874 to 0.0870) and pulled the 0.5-0.75 range onto the diagonal. After calibration, customers given about 0.6 buy about 60% of the time, which is what the agent needs.

  6. Limits. One split and three seeds. The crosses and settings were chosen on validation, so validation scores are a little optimistic; the test numbers are the fair comparison. Test differences of a few thousandths (0.581 against 0.585) are within noise.

Conclusion. The memorised rules do not improve the neural network, because the deep part learns the same interactions by itself. Deep only is the best of my three models on test and is level with the baselines. The wide part is still useful for one thing: its rules can be read by a CRM executive, which can help explain the model's decisions to the business.
